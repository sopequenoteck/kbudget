# Internationalisation

How k-budget names, writes and translates interface text, and the vocabulary
every translation must use.

**Status:** this document is written *before* any extraction. Neither client
follows it yet — Angular has no i18n library, and the existing Flutter ARB file
predates it. The migrations are KKS-325 (Angular) and KKS-326 (Flutter); from
then on, a key or a translation that contradicts this document is a bug.

Two audiences:

- **developers** adding or renaming a key — read [Keys](#keys) and
  [Writing strings](#writing-strings);
- **translators** — read [Principles](#principles) and the
  [Glossary](#glossary).

---

## Principles

1. **English is the source language and the default.** Every key exists in
   English first.
2. **French is maintained by the maintainer, at parity.** It is the language of
   the niche the project serves (France and West Africa) and must never lag
   behind English. Other languages are community-maintained.
3. **Angular is the reference client.** Keys are named when extracting Angular;
   Flutter reuses the same keys. When the two clients word the same thing
   differently, Angular wins, unless a documented exception says otherwise.
4. **The API does not translate.** It returns error codes; each client
   translates the code, never the `message` field. See
   [`api-errors.md`](api-errors.md).
5. **One build serves every language.** Translations load at runtime, so a
   self-hoster never picks a language when building or pulling an image.

## Keys

### Structure

A key has **exactly three segments**:

```
domain.context.element
```

```
transactions.form.amountPlaceholder
debts.value.borrowed
common.action.save
```

The first segment is **what the text is about**, never where the code lives:
Angular files accounts under `settings/`, Flutter has an `accounts` feature, and
both use `accounts.`.

### Domains

Closed list. Adding a domain is a change to this document.

| Domain | Covers |
|--------|--------|
| `accounts` | Bank accounts, balances, net worth, banks (bank names are data and are never translated) |
| `transactions` | Transactions, expense and income, transfers, balance adjustments |
| `recurring` | Recurring transactions |
| `subscriptions` | Subscriptions |
| `debts` | Debts, repayments, reminder snoozing |
| `budgets` | Budgets, unbudgeted spending |
| `categories` | Categories |
| `imports` | CSV import, import profiles, import drafts, category rules |
| `exchangeRates` | Exchange rates and the user's currencies |
| `notifications` | Notifications and reminders |
| `users` | User administration, invitations |
| `auth` | Sign-in, first-login reset, invitation acceptance, lock screen |
| `settings` | Preferences: theme, text size, language, time zone, navigation order |
| `onboarding` | Local or server mode selection (Flutter only) |
| `compatibility` | The client/server incompatibility screen (`/api/meta`) |
| `common` | Vocabulary shared by every domain |
| `errors` | Error messages |

**One exception: `dashboard`.** The dashboard is a screen, not a domain. It is
admitted only for text that belongs to no domain, such as a month-over-month
variation. Anything a domain owns goes to that domain: net worth is computed
from accounts, so it is `accounts.summary.netWorth`, even though only the
dashboard shows it.

### Contexts

Closed list, shared by every domain.

| Context | Covers | Example |
|---------|--------|---------|
| `page` | Screen title and subtitle, section headings | `debts.page.title` |
| `form` | Field labels, placeholders, hints, field-specific errors | `transactions.form.amount` |
| `list` | Column headers, row text, counters, groups, sort | `recurring.list.overdue` |
| `detail` | Text on the detail view of one item | `debts.detail.remaining` |
| `dialog` | Modals **and** bottom sheets | `accounts.dialog.deleteTitle` |
| `empty` | Empty states | `debts.empty.repaid` |
| `filter` | Filters and search | `transactions.filter.period` |
| `action` | Domain-specific verbs: buttons, menu items, FAB | `debts.action.repay` |
| `feedback` | What the app reports about an operation: in progress, succeeded, failed | `budgets.feedback.saved` |
| `summary` | Hero figures and totals | `debts.summary.net` |
| `value` | Values of a domain enum: types, statuses, frequencies | `debts.value.repaid` |

Rules that decide borderline cases:

- **Generic verbs go to `common.action`** (`save`, `cancel`, `delete`,
  `retry`). `domain.action` is for verbs that mean something in that domain
  only: *repay*, *snooze*, *mark as paid*.
- **A status shown as a badge, a filter chip and a switch is one `value`.**
  *Repaid* appeared four times in the old Flutter catalogue; it is
  `debts.value.repaid`, once.
- **`feedback` includes waiting states.** *Loading…* is
  `common.feedback.loading`; *Connecting…* is `onboarding.feedback.connecting`.

Two contexts exist **only under `common`**:

| Context | Covers | Example |
|---------|--------|---------|
| `nav` | Navigation labels, distinct from page titles | `common.nav.transactions` |
| `validation` | Constraint messages, including the API's `details[].code` | `common.validation.notBlank` |

And `errors` has **its own two contexts**:

| Context | Covers | Example |
|---------|--------|---------|
| `api` | One key per error code served by the API | `errors.api.passwordIncorrect` |
| `client` | Errors the API never sends: network, timeout, generic fallback | `errors.client.network` |

### Element

The third segment is **English, lowerCamelCase, and names what the text
designates** — not the widget that displays it.

**No suffix means the visible label.** A variant takes one suffix from a
closed list:

| Suffix | Use | Example |
|--------|-----|---------|
| *(none)* | Visible label | `transactions.form.amount` |
| `Placeholder` | Placeholder of an input | `transactions.form.amountPlaceholder` |
| `Hint` | Helper or secondary text | `accounts.form.activeHint` |
| `Aria` | Accessible label with no visible counterpart | `transactions.filter.searchAria` |
| `Title` | Title of a multi-part block | `accounts.dialog.deleteTitle` |
| `Message` | Body of a multi-part block | `accounts.dialog.deleteMessage` |

A block with a single, unqualified title uses the element `title`:
`debts.page.title`.

**Never name the widget.** `Button`, `Field`, `Picker`, `Switch`, `Label` and
`Badge` do not appear in keys: rebuilding a switch as a segmented control must
not rename a key, and a translator has no use for the information.

### Error codes

`errors.api` keys are the API codes converted **mechanically** from
SCREAMING_SNAKE_CASE to lowerCamelCase, with nothing dropped:

| API code | Key |
|----------|-----|
| `PASSWORD_INCORRECT` | `errors.api.passwordIncorrect` |
| `INTERNAL_ERROR` | `errors.api.internalError` |
| `VALIDATION_ERROR` | `errors.api.validationError` |

The validation codes in `details[].code` follow the same rule under
`common.validation`: `NOT_BLANK` → `common.validation.notBlank`, `SIZE` →
`common.validation.size`, and the fallback `INVALID_VALUE` →
`common.validation.invalidValue`.

A code the client does not know — a newer server can emit one — falls back to
`errors.client.generic`. Never to an empty message, never to the raw code.

### From Transloco to ARB

ARB keys become Dart getters, so they cannot contain dots. The Flutter key is
the Angular key with the dots removed and the next letter uppercased:

| Angular (Transloco) | Flutter (ARB) |
|---------------------|---------------|
| `transactions.form.amountPlaceholder` | `transactionsFormAmountPlaceholder` |
| `accounts.summary.netWorth` | `accountsSummaryNetWorth` |
| `errors.api.passwordIncorrect` | `errorsApiPasswordIncorrect` |

The conversion is reversible because domains and contexts are closed lists:
`debtsValueRepaid` can only split as `debts` + `value` + `repaid`.

### No legacy exceptions

The keys in the current `app_fr.arb` do not follow this convention: singular
and plural prefixes mixed (`debt*`, `debts*`), widget suffixes, French words
(`debtsFilterEnCours`). **All of them are renamed in KKS-326**, the
`errorCode*` block included. The French values are kept as translations; only
the keys change.

## Writing strings

### ICU MessageFormat, on both clients

Parameters and plurals use **ICU MessageFormat** in both catalogues, with
single braces. ARB supports it natively; Transloco uses the MessageFormat
plugin, which handles simple parameters (`{name}`) as well as plurals. **Never
set Transloco's `interpolation` option to single braces**: Transloco would then
interpolate before MessageFormat and empty every plural block (KKS-373, guarded
by a test). The same string is then written identically on both sides:

```json
"subscriptions.detail.paymentCount": "{count, plural, one {# payment} other {# payments}}"
```

```json
"subscriptions.detail.paymentCount": "{count, plural, one {# paiement} other {# paiements}}"
```

**Use plural categories (`one`, `other`), not exact matches (`=1`).** Each
language applies its own rules: in French, `one` covers 0 *and* 1, so the
string above renders *0 paiement* in French and *0 payments* in English, both
correct. Languages with more forms (Polish, Arabic) add `few` and `many` in
their own file; a hand-written `count > 1 ? 's' : ''` cannot do that.

### Rules

- **Whole sentences only.** Never build a sentence from fragments; a
  translator cannot reorder pieces spread over several keys.
- **No hard-coded case.** *BILAN MENSUEL* is written *Bilan mensuel*;
  uppercase is a style (`text-transform`, `TextStyle`), and some languages have
  no case at all.
- **No shared sentence with a noun parameter.** *Delete this {item}?* cannot be
  translated: French needs *ce compte* but *cette transaction*. Each domain
  keeps its own `dialog.deleteMessage`.
- **Amounts and dates are parameters, never text.** A translation receives a
  value already formatted for the display locale, and never embeds a currency
  symbol.

## Formats

**The display locale and the currency of an amount are independent.** A French
interface shows a CFA franc amount as *1 500 F CFA*; an English interface shows
the same amount as *F CFA 1,500*. The currency comes from the data (EUR, XOF,
USD, GBP, CHF, CAD, MAD), the separators and symbol placement from the locale.

- **Angular** reads the display locale from a single reactive source,
  `LanguageService.displayLocale()` (`fr` → `fr-FR`, `en` → `en-GB`), derived
  from the active language (KKS-373). Formatting pipes are impure and cache
  their formatters per locale, so a language change reformats values already on
  screen. Never pass a literal locale to `Intl`, `toLocaleString` or
  `localeCompare`.
- **Flutter** formats with `intl` (`NumberFormat.currency`, `DateFormat`), using
  the active locale. 22 hard-coded French locales (`'fr'`, `'fr_FR'`) remain,
  removed by KKS-326.

XOF has **no minor unit**: never display decimals for it, whatever the locale.

### Recurring transactions and subscriptions

**These two are different things, and a translation must keep them apart.**

- A **recurring transaction** is a structural obligation: rent, electricity, a
  salary coming in. It cannot be stopped without real consequences, and it can
  be income as well as expense. The recurring screen shows a monthly summary
  because the question it answers is *does my recurring income cover my
  obligations?*
- A **subscription** is an optional expense: streaming, a gym. Stopping it is a
  choice. It is always an expense.

Translating both as *subscription*, or both as *recurring payment*, erases the
distinction the product is built on.

| English | French | Notes |
|---------|--------|-------|
| Recurring transaction | Récurrence | *Recurring* alone as a screen title. Never *subscription* |
| Occurrence | Occurrence | One due instance of a recurring transaction |
| Skip | Passer | Skip one occurrence |
| Mark as paid | Marquer comme payée | |
| Monthly summary | Bilan mensuel | Recurring screen only |
| Subscription | Abonnement | Never *recurring* |
| Renewal | Renouvellement | |
| Monthly total | Total mensuel | Subscriptions screen |
| Weekly · Monthly · Yearly | Hebdomadaire · Mensuel · Annuel | Enum `Frequency`. Short forms: */week*, */month*, */year* |
